# CLAUDE.md — VionX

VionX is a Student & Family OS for Vietnamese students (Grade 1-12). It ships as an Android app (Expo) with Parent and Child modes, backed by Supabase, with a shared content library generated by Claude and reviewed by humans. Admin is a small web SPA. Launch content is Grade 2 and Grade 6 only (8 libraries, `docs/CONTENT_PLAN_vi.md`).

## Read order for every task
1. This file.
2. `docs/CONTRACT.md`. Always.
3. `docs/ARCHITECTURE.md`: only the sections the task touches.
4. `TASK_PACKS/<MODULE>.md`: the scope. Its "Out of scope" list is binding.
5. `docs/milestones/<DEP>_REPORT.md` for each dependency listed.
6. `docs/reference/VIONX_MASTER_SPEC_v1.3.txt`: only for a cited § or an unclear product rule. Its infrastructure sections (Mac mini, Docker, Ollama, Flutter, NestJS, Next.js, Vercel, Inngest) are superseded.

## Working loop
1. Check `docs/ROADMAP.md`: dependencies DONE, otherwise stop and report.
2. Branch `m<NN>-<slug>`; write `docs/milestones/<MODULE>_PLAN.md`.
3. Order: SQL migration → `packages/domain` rules + tests → `supabase/functions/api` routes + Zod schemas → worker/cron jobs → admin screens → mobile screens → Maestro flow.
4. `pnpm check` green (lint, typecheck, unit, API integration against local Supabase, openapi diff).
5. `pnpm acceptance <module>` passes.
6. Write `docs/milestones/<MODULE>_REPORT.md`, set the module to DONE in ROADMAP, open a PR. Stop.

If the module does not fit in one session, commit what is green, list remaining steps in the PLAN, push, stop.

## Hard rules (summary; the contract is authoritative)
- All client access goes through the `api` Edge Function; no direct table access from mobile/admin.
- Child data queries use `scoped(ctx)`; cross-household tests are mandatory.
- `assertConsent` before AI personalization, microphone, health or competition-area features.
- Ledgers append-only; event/reward handling idempotent.
- Library tables never contain personal data.
- Model calls only through `AiGateway`; model per task from `ai_task_config`; content building uses the Batch API.
- No secrets in code. Tests never hit paid APIs unless `AI_LIVE=1`.
- Do not widen scope; do not start the next module.
