# M09 — Offline, push, operations, alpha distribution
Depends on: M08   |   Refs: Master Spec §26, §28

## In scope
- **Offline (child):**
  - `GET /v1/students/:id/offline-pack` returns Today items, items and templates for planned skills, and the KaTeX assets needed.
  - Stored in expo-sqlite. Template variants are rendered on the device with the shared variant engine.
  - Action queue with client UUIDs; `POST /v1/sync/actions` is batched and idempotent.
  - Conflict rules per §26. Offline banner.
- **Push:** expo-notifications with FCM credentials; device tokens per user. The worker sends Today reminders (child), approval requests and weekly summaries (parent).
- **Ops:**
  - Sentry alerts.
  - Admin page `/system`: queue depth and dead letters, cron last runs, AI spend today per task from `ai_runs`, storage usage, tutor quota usage.
  - Supabase backups/PITR enabled, with a documented restore drill into a staging project.
  - Anthropic workspace spend limit documented.
- Analytics events (§28 list) into `ops.analytics_events`, IDs only.
- In-app feedback (child + parent) → `app.feedback_items` with an optional screenshot.
- **Distribution:** EAS production build (AAB), Google Play internal testing track, EAS Update channel for JS fixes, versioning policy in README.

## Acceptance
- Airplane-mode Maestro test: 2 tasks + 1 session offline → reconnect → exactly one completion each, correct XP.
- A push notification arrives on a real Android phone.
- The internal testing link installs on 2 devices.
- `docs/milestones/GATE_A_CHECKLIST.md` is all green.
