# M14 — Content factory: 500 items per subject, verification, review, quality loop
Depends on: M13   |   Refs: Master Spec §21.3, §32, §33.10-33.11; ARCHITECTURE §3-4; CONTRACT D6-D7

## Goal
Generalise the X01–X08 build scripts into an admin-driven factory that builds and maintains the shared library for any grade-subject.

## Flow (queue + batch stages)
1. **Plan**: the admin picks a grade-subject. The planner allocates **500 items** using ARCHITECTURE §3 rules (coverage first) and the grade-subject's `library.subject_profiles` row (TEMPLATE share, item-type mix, group/passage share, written share, read-aloud, image level). The admin can adjust per skill before launch.
2a. `PASSAGES` (Batch, Sonnet 5.5) for profiles with groups: original passages, poems, dialogues, picture scenes or experiment scenarios by genre and reading level, or PUBLIC_DOMAIN texts with a `source_note`. Never SGK reading texts verbatim.
2b. `MEDIA` (Batch, Sonnet 5.5) for profiles with images: simple SVGs or licensed icon ids, rendered and sanitised for review.
2. `GENERATE` (Batch, Sonnet 5.5). Cached prefix: style guide, schema, grade vocabulary list. Per-skill input: skill, objectives, top retrieved chunks with refs, `source_exercises` patterns, misconceptions. Output: items/templates (math.js or word-list params) with hints[4], worked solution, distractor feedback, tags, `tts_text`/`tts_lang`, group links and rubrics for written items.
3. `CHECK` (code):
   - schema;
   - exactly one correct answer;
   - math.js re-computation;
   - template constraint test over 1,000 seeds;
   - KaTeX parse;
   - readability by grade, and passage length within the profile range;
   - `tts_text` present where read-aloud is required;
   - SVG render + sanitising;
   - n-gram overlap with sources (reject copying);
   - near-duplicate detection (normalised text + trigram similarity, `pg_trgm`).
4. `VERIFY` (Batch, Haiku 4.5): blind solve, hint review, and age-appropriateness of passages and pictures. Disagreement → `DISPUTE` (Batch, Opus 5.5, ≤5% expected). A still-unresolved dispute → NEEDS_REVIEW.
5. **Status**: all checks pass and the verifier agrees with high confidence → `ELIGIBLE_BULK_APPROVE`; otherwise `NEEDS_REVIEW`.
6. **Review Queue** (§33.11) with keyboard shortcuts, variant re-roll for templates, source preview, passage view (review a group and its items together), picture preview, TTS preview and bulk approve for eligible items. Language groups and written-item rubrics are never bulk approved. Rejected slots auto-regenerate once.

## Maintenance (worker jobs)
- **Nightly stats**: `item_stats` from attempts. Outliers (calibrated difficulty off by ≥2 levels from the tag, p_correct < 0.1 or > 0.98 after N attempts, report rate above threshold) → NEEDS_REVIEW.
- **Weekly top-up**: skills whose unseen pool is below threshold for ≥X active students get new items through the same pipeline, with a budget cap per week from config.
- **Curriculum change**: affected skills' items are flagged for regeneration; nothing else is touched.

## Acceptance
- A full 500-item run for one grade-subject meets the coverage rule and its subject profile shares (±5 points).
- A Tiếng Việt 2 run produces passage groups, spelling templates and picture-choice items that pass validation.
- A planted wrong-answer item is caught.
- 20 items are reviewed in < 10 minutes.
- The report gives cost per approved item and the rejection rate per model.
