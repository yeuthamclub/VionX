# M01 — Identity & household
Depends on: M00   |   Refs: Master Spec §2, §6.1

## Data
`app.profiles(user_id → auth.users)`, `app.households(timezone)`, `app.household_memberships(role OWNER|GUARDIAN)`, `app.students(display_name, birth_year, grade, avatar)`, `app.child_credentials(child_login_id unique, pin_hash argon2id, failed_attempts, locked_until)`, `app.child_sessions(token_hash, device_id, expires_at, revoked_at)`, `ops.admin_permissions(user_id, permission)`.

## API
Parents sign in through Supabase Auth inside the app (native Google Sign-In, phone OTP). The API verifies the Supabase JWT.

Endpoints:
- `POST /v1/household`, `GET /v1/household`
- `POST /v1/students`, `GET/PATCH /v1/students/:id`
- `POST /v1/students/:id/reset-pin`, `POST /v1/students/:id/revoke-sessions`, `POST /v1/students/:id/disable`
- `POST /v1/auth/child/login {childLoginId, pin, deviceId}` → opaque token, stored in expo-secure-store
- `POST /v1/auth/child/logout`

## Rules
- Login ID is `vx-` plus 6 unambiguous characters. PIN is 4-8 digits.
- 5 failed PIN attempts → 15-minute lock. Rate limit per device and per login ID (`ops.rate_limits`).
- Child token: 32 random bytes, stored hashed, 30-day sliding expiry, revocable.
- A parent sees only their own households; anything else returns 404 (integration-tested).
- Event `ChildCreated`. Audit log for PIN reset, session revoke and disable.

## UI (mobile)
- Onboarding: choose Parent or Child.
- Parent: sign in, create household, children list, add child, one-time credential card (shareable as an image).
- Child: ID + PIN keypad. The device remembers the ID. A parent can switch a device to "child device" mode.

## Seed
SUPER_ADMIN user. Demo parent with Supabase test phone `+84900000001` and OTP `123456` (local only), with 3 children in grades 2, 6 and 9.

## Acceptance
Acceptance script + Maestro flow: parent OTP → household → 3 children → child login → 5 wrong PINs lock the account → parent resets PIN → child login OK.
