# M03 — Calendar, timetable & tasks
Depends on: M02   |   Refs: Master Spec §13

## Data
`app.school_subjects` (GDPT 2018 list), `app.school_timetable_entries`, `app.calendar_events` (types §13.1), `app.task_templates`, `app.task_assignments` (fields §13.2 + `rrule`), `app.task_completions(client_uuid unique)`, `app.task_proofs(storage_path)`.

## API
- `GET /v1/students/:id/calendar?from&to`
- CRUD for timetable entries and events
- `POST /v1/students/:id/tasks`, `PATCH /v1/tasks/:id`
- `POST /v1/tasks/:id/complete {clientUuid, proofPath?}`
- `POST /v1/tasks/:id/approve|reject`
- `POST /v1/uploads/sign`

## Rules
- A daily pg_cron job materialises recurring occurrences for the next 14 days (idempotent).
- Verification modes:
  - SELF_CHECK;
  - PHOTO_PROOF (goes to PENDING_APPROVAL);
  - PARENT_APPROVAL;
  - SYSTEM_VERIFIED (used by M06/M07).
- Completion is idempotent by `clientUuid`.
- Events: `TaskAssigned`, `TaskCompleted`, `TaskApproved`, `TaskRejected`.
- Children can only complete tasks, never edit them.

## UI (mobile)
- Parent: week calendar, timetable editor, task form (repeat, verification mode), approvals inbox with push badge.
- Child: today's tasks (replaced by Today in M07), complete with a camera photo (expo-image-picker).

## Acceptance
A recurring PARENT_APPROVAL task: the child completes it twice with the same clientUuid → one completion is stored → the parent approves → exactly one `TaskApproved` event.
