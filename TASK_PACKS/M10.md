# M10 — Book import, ingest runs & job framework
Depends on: GATE A   |   Refs: Master Spec §9, §33.1-33.4; docs/BOOK_PIPELINE_vi.md §2-3

## Goal
Admins import textbooks from the admin web. Heavy file work happens in the admin's browser; the server runs resumable, cached stages through queues and cron. Nothing runs on GitHub.

## Data (schema `library`, no personal data)
- `source_files(sha256 unique, bytes, storage_path, license_scope INTERNAL_REFERENCE|LICENSED|PUBLIC_DOMAIN, page_count)`
- `book_editions(series, title, grade, subject, book_type SGK|SBT|SGV|REFERENCE|READING, volume, publisher, curriculum_year)`, `book_versions`
- `source_pages(book_version, page_no, text_layer, text_quality GOOD|LEGACY_ENCODING|SCANNED|FORMULA_HEAVY|EMPTY, preview_path, route TEXT|AI, status)`
- `ingest_runs(book_version, status, current_stage)`
- `ingest_tasks(run, stage, page_from, page_to, status, attempts, input_hash, stage_version, output_path, batch_id, error, cost_usd)`
- `stage_cache(stage, stage_version, input_hash, output_path)`
- `human_corrections`

## Browser-side import (admin SPA)
1. Admin picks a PDF and fills metadata (§33.3).
2. The SPA computes sha256 and, with pdf.js, extracts the per-page text layer, renders 110-dpi previews and scores text quality:
   - diacritic ratio;
   - legacy TCVN3/VNI font names or mojibake;
   - characters per page;
   - math-symbol density.
3. With pdf-lib, the SPA splits pages routed `AI` into 10-page PDFs.
4. Everything uploads to signed URLs, then `POST /v1/admin/books/:id/ingest` creates the run.

## Server orchestration
- Each stage is a queue message on pgmq `ingest`, consumed by the `worker` function. Every stage is pure on `(input_hash, stage_version, params)`, so a cache hit skips it.
- Batch AI stages call `ai-batch` to submit and store `batch_id`; a pg_cron job every 10 minutes polls open batches, writes results and enqueues the next stage.
- Retry, cancel and resume per run and per task. Bumping `stage_version` re-runs that stage and everything downstream.
- Human corrections are re-applied after every re-run.
- M10 stages: `VALIDATE` (dedupe, page count, metadata) and `ROUTE` (decide TEXT vs AI per page from quality scores, overridable by the admin).

## UI (admin)
- Library list.
- Import wizard.
- Run view: stage timeline, page heatmap by route/status, logs, retry/cancel.
- Book Inspector shell (tabs §33.5).
- Dashboard KPIs, including AI cost per run.

## Acceptance
- The same PDF imported twice → one `source_files` row.
- A mixed PDF shows a correct TEXT/AI split.
- Killing the worker mid-run → the next cron tick resumes without redoing finished tasks.
- A `stage_version` bump re-runs only the affected stage(s).
