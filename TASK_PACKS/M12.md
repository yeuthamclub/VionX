# M12 — Structure & curriculum mapping
Depends on: M11   |   Refs: Master Spec §31.3-31.4, §33.6-33.8; CONTRACT D5

## Stages
1. `STRUCTURE` (single Sonnet 5.5 call): input = PDF outline + heading blocks with page numbers + TOC page blocks. Output = `book_structure_nodes` (chapter/lesson/section, page ranges, confidence). Code checks that ranges are contiguous and monotonic and cover all pages.
2. `SEGMENT` (code): assign blocks to lessons by page range and heading order.
3. `EXERCISES` (code): exercise/solution blocks → `source_exercises` (number, stem, parts, printed answer, page). These are used as style and difficulty patterns only.
4. `MAP` (Batch, Sonnet 5.5): one request per lesson. The cached system prompt holds the grade-subject skill backbone; the input holds the lesson title, SGV objectives and first blocks. Output = `content_mappings` (skill codes, rationale, confidence, status PROPOSED).
5. `PROPOSE_SKILLS`: lessons without a confident match → proposed new skills, each with a duplicate warning against the existing backbone.

## UI (admin)
- Structure Editor (tree drag/drop, split/merge, page re-map, approve TOC).
- Skill Builder.
- Knowledge Graph editor (React Flow, cycle detection, orphan warnings).
- Mapping review queue with bulk approve above a confidence threshold.
