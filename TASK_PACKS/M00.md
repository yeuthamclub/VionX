# M00 — Foundation
Depends on: –   |   Refs: ARCHITECTURE §1-2, §7; CONTRACT §2

## Goal
An empty but runnable VionX. The Android dev build talks to the Supabase `api` function, the admin SPA builds, and jobs and the AI gateway are wired.

## In scope
- pnpm workspaces + Turborepo monorepo per CONTRACT §2 (`apps/mobile`, `apps/admin`, `supabase/`, `packages/domain`, `packages/contracts`, `packages/ai`, `packages/tokens`, `scripts/acceptance/`); TS strict, ESLint, Prettier, Vitest.
- Root scripts from the CLAUDE.md command list that apply now (`dev:*`, `db:*`, `fn:serve`, `lint`, `typecheck`, `test`, `check`, `openapi`, `acceptance`, `ai:check`); later modules add the rest.
- Edge Functions import workspace packages through an import map in `supabase/functions/deno.json` (e.g. `@vionx/domain` → `../../packages/domain/src/index.ts`, npm deps as `npm:` specifiers). Packages imported by Edge Functions therefore use no Node built-ins and no build step.
- Supabase:
  - `config.toml` and migration `0001_base.sql` creating schemas `app`, `library`, `ops`.
  - Tables `ops.domain_events`, `ops.audit_logs`, `ops.ai_runs`, `ops.ai_task_config` (seeded with ARCHITECTURE §4 defaults), `ops.rate_limits`, `ops.analytics_events`.
  - Extensions `pgmq`, `pg_cron`, `pg_net`, `unaccent`.
  - RLS on, no client grants.
- `supabase/functions/api`: Hono app, request id, error shape, actor resolver skeleton, `GET /v1/health` (db, storage, queue, AI key present), OpenAPI at `/v1/openapi.json`.
- `supabase/functions/worker`:
  - pgmq consumer (batch read, visibility timeout, archive on success, dead-letter after N attempts);
  - pg_cron job that calls it every minute via `pg_net`;
  - outbox trigger `ops.domain_events → pgmq "events"`.
- `supabase/functions/ai-batch`: stub that calls `AiGateway.submitBatch` / `collectBatch` (real use from X01/M10).
- `packages/domain`: empty module layout plus one sample pure rule with a Vitest test, so `pnpm test` runs from day one.
- `packages/tokens`: VionX colour, type and spacing tokens.
- `packages/ai`:
  - `AiGateway` with `AnthropicProvider` (official `@anthropic-ai/sdk`, imported in Deno via `npm:`) and `FakeAiProvider`;
  - task-config lookup, `ai_runs` logging, `submitBatch` / `collectBatch`;
  - `pnpm ai:check` makes one tiny real call with `claude-haiku-4-5`.
- `packages/contracts`: Zod → OpenAPI → typed client (openapi-fetch).
- `apps/mobile`:
  - Expo (latest SDK), expo-router, TypeScript, VionX theme from `packages/tokens`;
  - Vietnamese strings with English fallback;
  - first-launch screen "Phụ huynh / Con";
  - development build profile in `eas.json`; Sentry.
- `apps/admin`: Vite + React + TS, TanStack Router/Query, login placeholder, navigation stubs from Master Spec §33.1, Cloudflare Pages config.
- `.github/workflows/ci.yml` on every PR: lint, typecheck, unit tests (`FakeAiProvider`, no paid calls); `supabase start` + API tests if they fit the CI time budget.
- `scripts/acceptance/m00` covering the checks below.
- README covering:
  - accounts to create (Supabase, Anthropic, Expo, Cloudflare, Google Play);
  - env vars;
  - running locally on an Android emulator.

## Out of scope
Business tables, auth flows, real screens.

## Acceptance
- `supabase start && pnpm fn:serve` → health OK.
- The Android dev build shows the health status returned by the API.
- An inserted `domain_events` row is consumed exactly once by the worker.
- `pnpm ai:check` succeeds with a real key.
- Admin `pnpm build` passes.
- `pnpm check` is green locally and the CI workflow passes on the PR.
