# M04 — Reward engine
Depends on: M03   |   Refs: Master Spec §14

## Data
`app.reward_rules` (system defaults + household overrides, Zod-validated JSON, versioned), `app.system_caps`, `app.xp_ledger(lifetime_xp_delta, rewardable_xp_delta, source_type, source_id, rule_id, idempotency_key)`, `app.coin_ledger`, `app.daily_reward_snapshots`, `app.reward_catalog_items`, `app.reward_redemptions`.

## API
- `GET /v1/students/:id/rewards/wallet`, `GET /v1/students/:id/rewards/ledger`
- `GET/PATCH /v1/household/reward-rules`
- CRUD `/v1/household/reward-catalog`
- `POST /v1/reward-redemptions`, `POST /v1/reward-redemptions/:id/approve|reject`

## Rules (`packages/domain/rewards`, with unit and property tests)
- 100 rewardable XP = 1 Coin. 1 Coin = 1,000 VND nominal, for display only.
- Weekday cap: 20 Coin.
- Weekend tiers: 20/30/40/50 per §14.2, decided from facts. Until M16/M18 exist, reading and activity facts come from completed tasks.
- Parents can lower caps but never raise them.
- XP above the daily cap counts toward lifetime XP only and does not roll over.
- Each `(source_type, source_id, rule_id)` is unique, and micro-action caps apply per rule.
- Ledgers are append-only. Corrections are reversal entries. Multi-ledger writes happen in one transaction.
- Worker consumers handle `TaskApproved`, `TaskCompleted` and later `LearningSessionFinished`. They are idempotent by event id and take a per-student advisory lock.
- Day-end conversion runs via pg_cron per household timezone.
- Events: `XpGranted`, `CoinGranted`, `RewardRedeemed`.

## UI (mobile)
- Parent: rules editor (showing system caps), catalog, redemption approvals, ledger.
- Child: wallet (XP, level, Coin, today's cap bar), catalog, redemption request.

## Acceptance
- Wednesday with 3,500 XP → exactly 20 Coin.
- Saturday at Tier 2 → at most 40 Coin.
- Replaying all events changes nothing.
- Timezone boundary tests pass.
