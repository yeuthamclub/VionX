# M02 — Consent & privacy core
Depends on: M01   |   Refs: Master Spec §6.1, §27, §34; CONTRACT §5

## Data
`app.policy_versions(type, version, locale, content_md, effective_at, requires_reconsent)`, `app.consent_records` (fields per §6.1), `app.privacy_requests`, `app.data_export_jobs`, `app.data_deletion_jobs`.

## API
- `GET /v1/policies/current`
- `GET /v1/students/:id/consents`
- `POST /v1/students/:id/consents/:type/grant|revoke`
- `POST /v1/students/:id/consents/:type/child-assent` (child actor)
- `POST /v1/privacy/export`, `GET /v1/privacy/export/:jobId`
- `POST /v1/students/:id/delete-request`, `POST /v1/account/delete-request`

## Rules
- `assertConsent` lives in the domain layer. `CORE_SERVICE` must be granted before any child can log in.
- Children aged 7+ must give assent for AI_PERSONALIZATION, MICROPHONE_SPEAKING and HEALTH_CONNECT_ACTIVITY.
- Revoking consent takes effect immediately, emits `ConsentRevoked`, and the worker drops queued jobs of that scope.
- Export runs in the worker: a zip of the household's JSON goes to private Storage, with a 24-hour signed URL and a push notification to the parent.
- Deletion: disable immediately, hard delete after 30 days via pg_cron. Ledgers are anonymised, not deleted.
- Account deletion must be reachable in the app (Google Play requirement) and from a public web page on the admin domain.
- Legal drafts go in `docs/legal/` (vi + en). They disclose Singapore hosting and AI processing by Anthropic, and are marked DRAFT.

## UI
- Parent onboarding consent step.
- Privacy Center: consents per child with history, accepted policy versions, export, delete.
- Child assent screen.

## Acceptance
- No child login is possible before CORE_SERVICE is granted.
- After AI consent is revoked, a guarded call returns `CONSENT_REQUIRED`.
- An export contains only the requesting household's data.
- A delete request blocks the child's login.
